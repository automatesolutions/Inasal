3. Database Setup

Step 1: MongoDB Atlas Setup

1. Create Account
Go to mongodb.com/cloud/atlas/register and sign up for free account
2. Create Cluster
Click "Build a Database" → Select M0 Free tier → Choose cloud provider and region → Click "Create"
3. Create Database User
Go to "Database Access" → Click "Add New Database User" → Choose "Password" authentication → Set username and password → Click "Add User"
4. Configure Network Access
Go to "Network Access" → Click "Add IP Address" → Select "Allow Access from Anywhere" (0.0.0.0/0) → Click "Confirm"
5. Get Connection String
Go to "Database" → "Connect" → Select "Connect your application" → Copy the connection string
Format: mongodb+srv://username:password@cluster.mongodb.net/?retryWrites=true&w=majority
Replace <password> with your actual password
6. Create Databases
For staging: bacolod_tourist_staging
For production: bacolod_tourist
Update connection string: ...mongodb.net/bacolod_tourist_staging or ...mongodb.net/bacolod_tourist

Step 2: Redis Cloud Setup

1. Create Account
Go to redis.com/try-free/ and sign up for free account
2. Create Database
Click "New Subscription" → Select "Free" tier → Choose cloud provider and region → Click "Activate"
3. Create Databases
Create two databases:
- bacolod-staging (for staging)
- bacolod-production (for production)
4. Get Connection Strings
Click on each database → Copy the connection string
Format: rediss://default:password@host:port

4. Git Branch Strategy

Branch Structure

main → Production (live website) staging → Staging (test website)

Create Staging Branch

# Create and switch to staging branch
git checkout -b staging

# Push staging branch to GitHub
git push -u origin staging

Workflow

1. Make changes locally ↓ 2. Commit and push to staging branch ↓ 3. Auto-deploy to STAGING environment ↓ 4. Test on staging URL ↓ 5. If good → Merge to main branch ↓ 6. Auto-deploy to PRODUCTION environment

5. Railway Deployment

Step 1: Create Railway Projects

1. Sign Up
Go to railway.app and sign up with GitHub
2. Create Staging Project
Click "New Project" → Name: Bacolod Tourist - STAGING → Connect GitHub repository
3. Create Production Project
Click "New Project" → Name: Bacolod Tourist - PRODUCTION → Connect GitHub repository

Step 2: Deploy Backend (Staging)

1. In STAGING Project → Click "New Service" → "GitHub Repo" → Select repository → Select backend folder
2. Settings → Source → Branch: staging
3. Go to "Variables" tab → Add all staging environment variables (see Environment Configuration section)
4. Railway will automatically build and deploy → Copy the URL: https://staging-backend.railway.app

Step 3: Deploy Backend (Production)

1. In PRODUCTION Project → Click "New Service" → "GitHub Repo" → Select backend folder
2. Settings → Source → Branch: main
3. Add all production environment variables
4. Copy the URL: https://production-backend.railway.app

Step 4: Deploy Strapi (Staging)

1. In STAGING Project → Click "New Service" → Select strapi-backend folder
2. Settings → Source → Branch: staging
3. Add environment variables: 
NODE_ENV=development
HOST=0.0.0.0
PORT=$PORT
APP_KEYS=staging-key-1,staging-key-2,staging-key-3,staging-key-4
API_TOKEN_SALT=staging-api-token-salt
ADMIN_JWT_SECRET=staging-admin-jwt-secret
TRANSFER_TOKEN_SALT=staging-transfer-token-salt
JWT_SECRET=staging-jwt-secret
Generate Random Keys:
PowerShell: -join ((65..90) + (97..122) + (48..57) | Get-Random -Count 32 | % {[char]$_})
Bash: openssl rand -base64 32
4. Deploy → Copy URL: https://staging-strapi.railway.app
5. Visit https://staging-strapi.railway.app/admin → Create admin account → Create API token → Add to backend environment

Step 5: Deploy Strapi (Production)

Follow same steps as staging, but:

  • Use PRODUCTION project
  • Set branch to main
  • Set NODE_ENV=production
  • Use production-specific keys

6. Vercel Deployment

Step 1: Deploy Staging Frontend

1. Go to vercel.com → Sign up with GitHub
2. Click "Add New" → "Project" → Import your GitHub repository
3. Configure:
  • Project Name: bacolod-tourist-staging
  • Framework Preset: Next.js
  • Root Directory: frontend
4. Settings → Git → Production Branch: staging
5. Add environment variables: 
NEXT_PUBLIC_API_URL=https://staging-backend.railway.app
NEXT_PUBLIC_STRAPI_URL=https://staging-strapi.railway.app
6. Click "Deploy" → Copy URL: https://bacolod-tourist-staging.vercel.app

Step 2: Deploy Production Frontend

1. Create new project → Import same repository
2. Configure:
  • Project Name: bacolod-tourist-production
  • Framework: Next.js
  • Root Directory: frontend
3. Settings → Git → Production Branch: main
4. Add environment variables: 
NEXT_PUBLIC_API_URL=https://production-backend.railway.app
NEXT_PUBLIC_STRAPI_URL=https://production-strapi.railway.app
5. Deploy → Copy URL: https://bacolod-tourist-production.vercel.app

7. Environment Configuration

Staging Environment Variables

Backend (Railway - Staging)

# Database
database_url=mongodb+srv://username:password@cluster.mongodb.net/bacolod_tourist_staging?retryWrites=true&w=majority

# Redis
redis_url=rediss://default:password@staging-redis-host:port

# JWT
jwt_secret_key=staging-jwt-secret-key-32-chars-minimum
jwt_algorithm=HS256
jwt_expiration_hours=24

# Production Settings
dev_mode=True
dev_mode_bypass_otp=True

# Anthropic API

anthropic_model=claude-3-haiku-20240307

# Email
smtp_host=smtp.gmail.com
smtp_port=587
smtp_user=your-email@gmail.com
smtp_password=your-gmail-app-password

# CORS
ALLOWED_ORIGINS=https://bacolod-tourist-staging.vercel.app,http://localhost:3000

strapi_api_token=your-strapi-api-token

NEXT_PUBLIC_STRAPI_URL=https://staging-strapi.railway.app

9. Troubleshooting

Common Issues

1. CORS Errors

Problem: Frontend can't connect to backend
Solution: Check ALLOWED_ORIGINS in backend environment variables. Ensure frontend URL is included. Remove * in production.

2. Database Connection Failed

Problem: Can't connect to MongoDB
Solution: Verify connection string, check MongoDB Atlas network access (should allow all IPs), verify database name, check username/password.

3. Build Failures

Problem: Deployment fails during build
Solution: Check build logs, verify dependencies, check for syntax errors, ensure correct Node.js/Python versions.

4. Environment Variables Not Working

Problem: App can't read environment variables
Solution: Verify variables are set in Railway/Vercel dashboard, check variable names match exactly, restart services, for Next.js ensure NEXT_PUBLIC_ prefix.
