System Architecture Flowchart

📥 Write Path (Data Ingestion)

1. Airtable (Source Data)

Contains restaurant information: name, url, description, image, etc.

⬇️

2. Make.com (Automation Platform)

Processes and transforms data through multiple modules:

  • • Iterator - Processes each record
  • • Set Variables - Transforms data
  • • Router - Routes data
  • • Text Aggregator - Combines data
⬇️

3. ngrok (Tunnel - Development Only)

Creates HTTPS tunnel to local Strapi instance

https://xxx.ngrok-free.dev → http://localhost:1337
⬇️

4. Strapi (Content Management System)

Stores and manages recommendation data

Content Type: Recommendation
Field: restaurant (JSON type)
{ "data": { "user": 18, "restaurant": [ {"name": "Restaurant 1", ...}, {"name": "Restaurant 2", ...} ] } }

Write Endpoint

POST https://xxx.ngrok-free.dev/api/recommendations
Headers: Authorization: Bearer STRAPI_API_TOKEN Content-Type: application/json Body: { "data": { "user": 18, "restaurant": [...] } }

1. Frontend (Next.js React App)

frontend/src/app/dashboard/page.tsx

User clicks "Restaurants" section

Line 33: recommendationApi.getRecommendations()
⬇️

2. API Client (Frontend HTTP Client)

frontend/src/lib/api.ts

4. Recommendation Routes (Orchestration Endpoint)

backend/app/routes/recommendation_routes.py

6. Strapi (Content Management System)

Queries, filters, and returns recommendation data

7. Strapi Client (Processes Response)

Parses response, handles Strapi v4/v5 format, extracts fields

⬇️

8. Recommendation Routes (Formats Response)

frontend/src/app/dashboard/page.tsx

Read Endpoint

GET http://localhost:8000/api/recommendations
Headers: Authorization: Bearer JWT_TOKEN (from FastAPI auth) Response: { "hotels": [], "restaurants": [...], "entertainment": [], "tourist_spots": [], "secret_recommendations": [] }

📁 Key Files

Write Path Files

  • Make.com Scenario - Cloud automation platform
  • ngrok - Tunnel service (development only)
  • Strapi Admin - Content Manager → Recommendation

Read Path Files

  • frontend/src/app/dashboard/page.tsx - Frontend UI component
  • frontend/src/lib/api.ts - Frontend API client
  • backend/app/main.py - FastAPI application entry point
  • backend/app/routes/recommendation_routes.py - Orchestration endpoint
  • backend/app/strapi_client.py - Strapi API wrapper
  • Strapi - Content Management System

🔄 Data Transformations

Airtable Format:
{name, url, description, match_score, category, image}
⬇️
Make.com Processing:
Transforms → Validates → Aggregates
⬇️
Strapi Storage Format:
{ "data": { "user": 18, "restaurant": [ {name, url, description, match_score, category, image}, ... ] } }
⬇️
FastAPI Response Format:
{ "hotels": [], "restaurants": [...], "entertainment": [], "tourist_spots": [], "secret_recommendations": [] }
⬇️
Frontend Display:
React Components → Cards → Images → Links

📊 Summary

Write Path: Airtable → Make.com → ngrok → Strapi (direct)
Read Path: Frontend → FastAPI → Strapi (orchestrated)

Key Points:

  • ✅ FastAPI acts as the orchestration layer for reads
  • ✅ Strapi is the single source of truth for data storage
  • ✅ Make.com writes directly to Strapi (no FastAPI in write path)
  • ✅ Frontend always goes through FastAPI for data retrieval
